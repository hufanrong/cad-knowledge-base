# WorkBuddy 项目最终目标与总体架构总纲

> **文档性质**：项目纲领（老板 2026-08-18 确立，不可随意变更，后续开发必须对齐）
> **保存位置**：docs/PROJECT_MASTER_PLAN.md

---

## 一、项目最终目标

面向工程安装、调试、施工和项目管理的**本地工程 AI 系统**。

> 建立一个能够理解整个工程项目的"工程数字知识系统"，让 AI 能够理解项目中的设备、工艺、结构、管道、材料、厂家资料、库存、装箱单、施工资料以及它们之间的关系。最终让 AI 具备接近一名熟悉项目资料的工程师的能力。

## 二、核心设计理念

工程资料（工艺图/结构图/PID/管道图/设备台账/厂家图纸/说明书/BOM/库存/装箱单/施工方案/现场照片）只是"资料载体"。

真正要建立的是：

```
文件 → 工程信息 → 工程实体 → 工程关系 → 工程知识网络 → AI工程推理
```

即：**工程实体 + 工程属性 + 空间关系 + 工艺关系 + 物资关系 + 施工关系 + 文件证据**。

## 三、需要理解的工程实体

Project / Area / Workshop / System / Equipment / Component / Foundation /
Structure / Building / Platform / Pipeline / Valve / Instrument /
Electrical Equipment / Material / Part / Supplier / Manufacturer / Package /
Drawing / Document / BOM / Inventory / Inspection / Weld / Location /
Parameter / Event / Construction Record / Photo

## 四、需要建立的关系

典型：Equipment → Component / Manufacturer / Foundation / Structure /
Platform / Pipeline / Valve / Instrument / Drawing / Document / BOM /
Package / Inventory / Installation Record

## 五、跨专业资料关联（核心难点）

例：工艺布置图（设备位号/位置/方向/相邻设备/管道接口）↔ 结构图（轴网/柱网/梁/基础/平台/标高/结构尺寸）

即使工艺图中没有基础编号、结构图中没有设备位号，也必须通过**空间位置、轴网、几何关系**建立候选关系（如 K-205 ↔ Foundation F21~F24），并附证据与置信度。

## 六、PID 与管道拓扑

建立 设备 ↔ 管道 ↔ 阀门 ↔ 仪表 ↔ 上下游设备 的完整工艺拓扑
（PID + 工艺布置图 + 管道平面图 + 管道 ISO 图联合）。

## 七、厂家资料消歧

厂家资料用 Model/Serial No.，不用项目位号。需综合厂家/型号/规格/尺寸/重量/功率/序列号/采购编号/合同/技术协议/台账/铭牌判定对应 K-205，**必须有证据和置信度，不能仅凭名称相似**。

## 八、BOM / 装箱单 / 库存 / 安装状态

能回答："这个装箱单属于哪个设备？""哪些零件没到货？""哪些已安装？""哪些还在仓库？"

## 九、工程空间关系

理解 轴网/坐标/标高/设备中心/基础中心/柱/梁/平台/楼梯/管道/支架/建筑边界；
建立 located_in / supported_by / installed_on / connected_to / adjacent_to / above / below / inside / outside / aligned_with。

## 十、工程证据体系

任何 AI 建立的关系都必须保存：来源文件、图号、页码、CAD 实体、坐标、截图/证据位置、匹配依据、置信度。

## 十一、事实 vs AI 推断（必须区分）

- 原始事实：厂家图纸写"重量135t"（RAW FACT）
- AI 推断：某基础属于 K-205（INFERENCE）
- **禁止把 AI 推断伪装成工程事实**。

## 十二、资料冲突处理

台账 120t vs 厂家图 135t → 系统必须报告冲突，**不得自行选择**；保留双方来源/版本/时间/差异/可信度，等待人工确认。

## 十三、版本管理

Rev.A/B/C：识别当前有效/历史/作废版本，不得无差别混用。

## 十四、人工确认

AI 关系可被 确认/否决/修改/人工指定；人工确认后成为项目级知识，AI 优先使用。

## 十五、最终 AI 应能回答的问题

基础归属、K-205 对应基础/厂家/厂家资料/所需资料/零部件/到货状态/螺栓库存、P-205 连接与阀门、相关图纸/施工记录/安装状态、基础标高、推断依据、重量冲突原因。

## 十六、关系网络

项目 → 车间/系统 → K-205 → {工艺(PID→管道→阀门仪表)、空间(基础/平台/柱梁轴网)、厂家(图纸/说明书/技术协议)、物资(BOM→装箱单→库存→安装)}

## 十七、技术路线

不依赖单一大模型。组合：
CAD解析 + PDF解析 + Word解析 + Excel解析 + OCR + 工程实体识别 + 编号识别 + 几何分析 + 空间配准 + 规则引擎 + 关系/图数据库 + 向量检索 + 大模型 + 人工确认。

分工：确定性数据→数据库；空间关系→几何算法；工程关系→关系/图数据库；相似内容→向量数据库；复杂语义→大模型；最终判断→AI+证据+人工确认。

## 十八、开发原则（阶段化，强制）

阶段0 现有系统审计 → 阶段1 完整资料入库 → 阶段2 工程实体层 → 阶段3 实体消歧 → 阶段4 工程关系层 → 阶段5 工艺图/结构图空间配准 → 阶段6 PID/管道拓扑 → 阶段7 厂家/BOM/装箱单/库存关联 → 阶段8 版本/冲突/证据系统 → 阶段9 工程AI助手 → 阶段10 工程自动分析和辅助决策。

每阶段：先分析 → 制定方案 → **等待确认** → 开发 → 测试 → 备份 → 验收。
**禁止一次性大规模修改整个系统。**

## 十九、当前阶段定位

工程资料尚未全部导入。当前优先级：
1. 保护现有系统
2. 资料库架构支持未来工程实体和关系
3. 完善文件导入、完整保存原始资料、统一文件ID、文件元数据、解析状态、版本基础
4. 为未来工程实体层预留接口

**当前阶段：可以提取信息，但不要过早确定复杂工程关系。** 等资料基本完整后再 File → Entity → Relation → Knowledge Graph。

## 二十、最重要的原则

最终目标不是"让 AI 搜索文件"，而是**"让 AI 真正理解整个工程项目"**。

任何开发必须问：这个功能能否让 WorkBuddy 更好地理解**工程实体、工程关系、工程空间、工程物资、工程施工过程**？如果只是表面功能却破坏未来工程知识模型 → 暂缓。

所有工程数据必须：**可追溯、可验证、可更新、可回滚、可人工确认**。
